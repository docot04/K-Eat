K-Eat API — API TEST INPUT / EXPECTED OUTPUT

======================================================================
COMMON RESPONSE SHAPES
======================================================================

SUCCESS:
{
  "success": true,
  "message": "<message>",
  "data": <expected data>
}

PAGINATED SUCCESS:
{
  "success": true,
  "message": "<message>",
  "data": [ ... ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 0,
    "totalPages": 0
  }
}

VALIDATION / APPLICATION ERROR:
{
  "success": false,
  "message": "<expected error message>"
}

Protected endpoints require:
Authorization: Bearer <JWT>

Database starts completely empty.
Use returned IDs/tokens from earlier successful requests in later requests.


======================================================================
1. HEALTH
======================================================================

GET /api/health

INPUT:
No headers required.
No body.

EXPECTED OUTPUT:
HTTP 200
{
  "success": true,
  "message": "K-Eat API is running",
  "data": {
    "status": "ok"
  }
}

EDGE INPUT:
GET /api/health with any query string.

EXPECTED OUTPUT:
HTTP 200 with the same health response.


GET /api/health/db

INPUT:
No headers required.
No body.

EXPECTED OUTPUT WHEN DATABASE IS REACHABLE:
HTTP 200
{
  "success": true,
  "message": "Database reachable",
  "data": {
    "database": "ok"
  }
}

EDGE INPUT:
Call while PostgreSQL is unavailable.

EXPECTED OUTPUT:
HTTP 503
{
  "success": false,
  "message": "Database unreachable"
}
